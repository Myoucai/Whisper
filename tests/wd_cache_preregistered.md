# 收口 ③：`wd` 的内容寻址缓存（预注册）

2026-09-21 立项。仿前几份：**判据先写死，再动代码**。

## 目标与理由

`wd run` 现在每次都重跑一遍 gcc。设计文档（`docs/independence-design.md`
Step 3 节）早就写了要做内容寻址缓存，一直没做。

## 设计决定（提前写明）

**缓存的是 gcc 的产物，缓存键 = hash(生成的 C 文本 ++ `runtime.c` 内容 ++ cc 名)。**

- **为什么不把"编译器版本"放进键**：同一份 C 经同一个 cc 出来就是同一个二进制，
  所以不需要记住"是谁生成的"。把编译器身份放进键反而会引入一条**脆弱不变式**
  ——改了 `wd` 却忘了 bump 版本号，缓存就会一直吐旧产物。
  把 **生成的 C** 当键的原料，这条不变式就自动成立。
- **为什么键里必须有 `runtime.c`**：它以 `#include "runtime.c"` 的形式被引用，
  **不在 C 文本里**。只哈希 C 文本的话，改了运行时不会失效。
- **哈希函数**：多项式 64 位（`h = h*1099511628211 + byte`，i64 自然回绕），
  结果拼上**原文长度**。不做加密强度——这是本机 `target/` 下的构建缓存，
  输入非对抗。长度入键是为了让"内容不同但哈希撞车"在长度上先分道。
- **缓存位置**：`<WHISPER_ROOT>/target/whisper-cache/<key>`。
- **只缓存 `wd run` 的产物**（`wd build` 的输出路径由调用者指定，命中也要复制
  一次，收益相同；两者共用同一段代码，不特判）。

## 判据

- **C-1（正确性，最重要）** 对同一程序：第一次 `wd run` 与第二次 `wd run`
  的**输出逐字节相同**，且都与"从零编译并直接运行产物"相同。
- **C-2（真的命中了）** 第二次调用**不再生成 `W_*` 函数**——判据是第二次
  比第一次快，且缓存目录里出现了对应条目。**用可观测的事实，不用感觉**：
  在缓存目录里的文件数从 0 变 1，且第二次的 wall time 明显更短。
- **C-3（改输入必失效）** 改**源码** → 新条目（旧条目仍在），输出随之改变。
- **C-4（改运行时必失效）** 改 `runtime.c`（判据用临时追加一个注释再还原，
  或用 `WHISPER_ROOT` 指向一份改过的副本）→ **不得命中旧条目**。
- **C-5（零回归）** 既有 wd 冒烟四条、`w2_wd_output_matches_c2_byte_for_byte`、
  `wd_driver_compiles_and_runs_when_present` 全过；六闸与固定点不回归。
- **C-6（失败不进缓存）** gcc 失败时**不得**写入缓存条目——否则一次偶发失败
  会被永久记住。

## 反向判据（什么算失败，提前写明）

- 为了省事把缓存键设成"源码文件路径 + mtime" → **失败**：改内容不改 mtime
  的工具链会命中错产物，而且 `wd` 是零 Rust 驱动，不该依赖时间戳。
- 失败时也写缓存 → **失败**（C-6）。
- 命中后不产出调用者要的 `<out>` → **失败**：那是偷偷改契约。
  `wd run <src> <out>` 仍必须留下 `<out>`。

  其余走 `cp`，用既有的 `"OS" "" wd-env "Windows_NT" str-eq?` 判平台。

- `wd-build` 里：算键 → `wd-real` 探缓存 → 命中则 `wd-cp` 到 `<out>` 并伪造

### 两次实测的失败形态

两次都是 `whisper: type error: expected ptr`，**首次调用**（未命中 → gcc →
回填）就崩，缓存目录一直是空的。第二轮我按静态检查改掉了两处明显的栈错
（回填分支里 `drop drop` 多弹了一个本地量、store 路径多了一个把 src/dst 弄反的
`swap`），**仍然是同一个错**——说明还有第三处，而它在我这一轮的预算内没定位到。

### 下一轮从哪里接（给接手的人省时间）

用**二分法把回填路径摘出来**，而不是继续读代码：

1. 先把回填整段注释掉，只留"算键 + 探缓存（必然未命中）+ 原 gcc 路径"——
   若这样能跑，问题就在回填段；若不能，问题在算键段（怀疑 `wd-hash` 的
   `@fold` 体在自举链接的融合路径上拿到的栈形状与预期不同——`{ swap p * swap + }`
   假设的是 `[acc, elem]`）。
2. 算键段里 `wd-hash` 单独验：喂一个已知串，看是否稳定、是否随内容变。
   **这一步上次没有做**，是这次返工的直接原因。
3. 回填段注意：`wd-real` 拿不到产物时的分支只能 `drop` 一个（`realout`），
   不是两个。
