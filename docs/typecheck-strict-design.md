# typecheck strict 默认——设计注与 J-3 战报（2026-09-04）

状态：**未达成默认翻转**，如实归档。目标（strict 默认 + `--no-strict-types`
逃逸口）的前置条件是"全套零误报"；本轮把误报从 7 处压到过 0，又在新
 fronts 上回摆，最终回退到稳定基线（Lexicon 6 处警告、workspace 全绿）。

## 为什么难（根因清单，按战果顺序）

1. **@each/@map 引号签名约束过强**（已修，保留）：expect_ref 要求
   引号 t→t 净零，而 @each 体合法地"消费元素 + 追加多输出"——放宽为
   仅检查 Ref 形状。这一条消掉大部分 Lexicon 误报。
2. **?? 臂合并只取 last()**（已修，保留）：多输出臂（[status text]）
   被截成单输出，调用点 swap 下溢——改为逐槽位合并。**注意**：该修复
   依赖词签名推断正确，单独存在时会被下一条的坏签名放大。
3. **词签名输入元数推断**（两遍法，试了三版，全部回退）：旧 min_depth
   法对"体首即消费"的词（mem?）给出 0 输入；两遍补位法能数对，但
   补位值会被后续 expect 消费（成对 expect 只计 1）、WordRef 全元数
   补位过计、quote 内折叠/循环体各自需要独立栈模型——每修一处，
   kv 态词（Lexicon 的主体风格）在新位置冒出误报。这不是补丁能收口
   的，是**近似 checker 的结构性边界**。
4. **http-* 内建签名缺失**（已修，保留）：http-req(4→3) 等加入
   builtins 表。

## 结构性结论

要零误报 + strict 默认，需要重设计而非修补：

- **多态变体推断**：每个词按调用点上下文实例化（当前单形签名一旦
  被一个调用点污染，全程序连锁）；
- **引号栈合同**：@each/@map/@fold 的体按"入口栈形"参数化检查
  （当前引号体从固定单元素栈起查）；
- **kv 态词**：kv-get/kv-set 的字符串键在类型层不可区分，词体内
  "` 模式"造成检查器视角的栈序与运行时不同——需要 effect 行
  （A-SK 键序）而不是值类型。

三者的工作量各自 ≈ Nth/Append 修复的 10 倍量级，且互相耦合。
